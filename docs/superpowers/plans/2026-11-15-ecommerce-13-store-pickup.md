# Store pickup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Store pickup shipping module: per-market rates and stores, stores offered to the storefront inside the shipping option, store chosen at checkout, a no-carrier Ship that can swap the store and sends a new "Ready for pickup" e-mail.

**Architecture:** A `store-pickup` carrier provider (no credentials) whose config holds `{ name, tax, rates, stores }`, mirroring how DPD keeps `services` in its config and saves them through a dedicated settings endpoint. The quote adapter returns one option carrying `pickupPoints`. The order keeps the store in the existing `pickupPoint` field (same shape as a DPD point), so the order sheet, address lock and method changes already work; DPD-only paths are guarded by `isDpdPickup`. Ship gains a third mode `STORE_PICKUP` that never calls a carrier.

**Tech Stack:** Strapi 5 plugin (TypeScript), React admin with `@strapi/design-system`, vitest.

**Spec:** `docs/superpowers/specs/2026-11-15-store-pickup-design.md` (approved; section 11 holds the final rulings). Delivery uses the existing `DELIVERY_CONFIRMATION` e-mail (user, 2026-11-15).

## Global Constraints

- Provider id `store-pickup`, category `carrier`, service id `STORE`, not exclusive, `fields: []`, no `testConnection`.
- Default names `{ en: 'Store pickup', pt: 'Levantamento em loja' }`; default tax 23.
- Store ids: `st_` + 10 lowercase alphanumerics, generated by the server when a store arrives without an id; existing ids are kept.
- Store fields: `name` (required, ≤ 120), `address` (required, ≤ 200), `address2` (optional, ≤ 200), `postalCode` (required, ≤ 20), `city` (required, ≤ 100). Country is derived: `PT` for markets `PT` and `PT-ISL`, otherwise the market code.
- At most 100 stores per market.
- A store's postal code must fall in its market: `marketOf(country, postalCode, storeMarkets) === market`, else `STORE_MARKET_MISMATCH` on its path.
- Do not change behaviour of Manual shipping, CTT, DPD, or any non-ecommerce module.
- Never log customer data. Commit with explicit paths (never `git add -A`); never touch `.yalc/` or `yalc.lock`. Commit trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. After each commit: `git branch -f main HEAD`. No push.
- Checks: `npx tsc -p server/tsconfig.json --noEmit`, `npx tsc -p admin/tsconfig.json --noEmit`, `npx tsc -p tests/tsconfig.json --noEmit`, `npx vitest run`.
- Admin copy: English and Portuguese (pt-PT, with accents) in `admin/src/core/translations/{en,pt}.json`.

## Review Focus

1. A store removed from settings after the order was placed: Ship still shows the order's store (selected) and can ship to it; checkout and swaps only accept stores from the current config. → Task 4 test `ships to the order's store even after it was removed from settings`.
2. Module turned off with open Store pickup orders: not quoted any more, but Ship still works. → Task 2 test `carrierFor forShipment returns store-pickup while inactive`; Task 4 test `ships an old store pickup order with the module off`.
3. A `pickupPointId` from another market (or a DPD PUDO id) at checkout → `PICKUP_POINT_INVALID`, never accepted. → Task 3 test.
4. A DPD Pickup order must behave exactly as before (search, carrier request to the point, edit flows). → existing DPD suites stay green unchanged; Task 3 adds `DPD pickup still searches DPD`.
5. Swapping the store at Ship to one of another market, or to an unknown id → `PICKUP_POINT_INVALID`, nothing written. → Task 4 test.

- Produces in `domain/pickupPoints.ts`: `isDpdPickup(providerId, serviceId)` (the old meaning), `isStorePickup(providerId, serviceId)` (`store-pickup` + `STORE`), `isPickupMethod` = either. - Switching between DPD Pickup and Store pickup on an order: the new method needs a new point (a stored point of the other kind is not kept). Decide by method: the stored point is kept only if the order's current method is of the same kind.
